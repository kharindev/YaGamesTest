# ЯИ Тест — QA-аудитор Яндекс Игр

Расширение Chrome/Edge/Opera для проверки черновиков и опубликованных игр на Яндекс Играх.

Главный экран показывает общий прогресс. Одновременно открыт один пошаговый сценарий. Расширение сохраняет ответы, SDK-события, предупреждения и скриншоты, а затем экспортирует самостоятельный HTML-отчёт.

Автоматически измеряется:

- время от начала навигации до `ysdk.features.LoadingAPI.ready()`;
- время инициализации SDK;
- число сетевых запросов;
- переданный и декодированный объём ресурсов;
- ручные скриншоты текущего этапа проверки.
- журнал SDK-событий;
- JavaScript-ошибки и ошибки рекламы;
- повторные `GameplayAPI.start()`/`stop()`;
- Game Ready дольше 10 секунд и таймаут 90 секунд;
- внешние сетевые источники и самые тяжёлые ресурсы.

## Проверка покупок

1. Отменить первую покупку: `purchase()` должен вернуть ошибку, игра продолжить работу, награда не начислиться.
2. Совершить обычную покупку: расширение фиксирует `purchase()`, делает снимки до и после и проверяет начисление.
3. Совершить ещё одну расходуемую покупку и на экране успешной оплаты перезагрузить страницу, не нажимая «Продолжить».
4. После запуска расширение фиксирует обязательные `getPurchases()` и `consumePurchase()`, затем делает итоговый снимок награды.
5. `GOOD` возможен только при прохождении всех трёх сценариев. Токены покупок не записываются в журнал и отчёт.

## Проверка сохранений

1. Нажать «Начать».
2. Выполнить действие, сохраняющее прогресс. Расширение отслеживает `player.setData()`, `player.setStats()`, Web Storage и записи IndexedDB.
3. Расширение покажет вызванный метод и ответ SDK в отчёте.
4. Открыть на экране данные, которые должны сохраниться, и нажать «Снимок и перезагрузка». Снимок делается до перезагрузки.
5. После Game Ready снова открыть эти данные и ответить, сохранились ли они.
6. При ответе расширение делает второй снимок. Оба кадра и ход проверки видны в разделе теста; результат будет `GOOD` или `FAIL`.

## Проверка rewarded

Сценарий показывает по одному вопросу, фиксирует `showRewardedVideo`, `onOpen`, `onRewarded`, `onClose`, ответы о звуке и паузе, делает два скриншота и формирует результат `GOOD`, `FAIL` или `SKIP`.

## Проверка звука

Сценарий спрашивает, есть ли в игре звук, затем считает вызовы `AudioContext`, `play()` у `<audio>` и `<video>`, фиксирует уход вкладки в фон и задаёт вопросы про системный плеер, остановку звука при потере фокуса и его возврат. Результат `GOOD` только если системный плеер не открывался, а звук корректно замолкал и возвращался; `SKIP`, если звука нет.

Счётчики показывают обнаруженные вызовы, но не доказывают отсутствие системного плеера — это подтверждает человек.

## Проверка языка

Сценарий работает без Debug Mode. Расширение меняет локаль и `Accept-Language` вкладки через Chrome DevTools Protocol, перезагружает игру, сверяет выбранный язык с `environment.i18n.lang`, запрашивает визуальное подтверждение перевода и сохраняет снимок. В селекторе доступны все официально заявленные языки Яндекс Игр.

## Архитектура проверок

- `checks/registry.mjs` — единый реестр подключённых проверок.
- `checks/*.mjs` — независимые сценарии сохранений, покупок, рекламы, языка, лидербордов, интерфейса и модерации.
- `test/*.test.mjs` — модульные и интеграционные проверки расширения.
- `background.js` — очередь сообщений по вкладке, хранение состояния и общие сервисы `context.capture(label)`, `context.reload()` и `context.gameFrameUrl` (кадр, где SDK инициализировался; сигналы из других кадров отбрасываются).
- `page-monitor.js` — перехватывает события SDK; `content.js` передаёт их фоновому скрипту.

Чтобы добавить проверку, создайте `checks/<id>.mjs` с тем же интерфейсом и добавьте её в `checks/registry.mjs`. Оверлей, состояние и маршрутизация подключатся автоматически. Для проверки переходов добавьте тест в `test/*.test.mjs` и запустите `npm test`.

Состояние каждой проверки хранится в `run.tests[id]`.

## Установка

1. Откройте `chrome://extensions` (или `edge://extensions`).
2. Включите «Режим разработчика».
3. Нажмите «Загрузить распакованное расширение».
4. Выберите эту папку.
5. Откройте черновик игры в Яндекс Играх.
6. Нажмите значок расширения — поверх игры откроется оверлей.
7. Нажмите «Перезагрузить игру», чтобы получить чистый замер.

## Как трактуется результат

Официальные требования Яндекс Игр:

- `LoadingAPI.ready()` должен вызываться при реальной готовности игры;
- при проверке индикатор должен стать зелёным в течение 90 секунд;
- все файлы игры в распакованном виде должны занимать не более 100 МБ.

В интерфейсе также используются наши практические ориентиры, которые не являются требованиями Яндекса:

- Game Ready до 5 секунд — хорошо;
- 5–10 секунд — допустимо;
- больше 10 секунд — рекомендуется оптимизация;
- до 10 МБ начальной передачи — хорошо для мобильного запуска;
- 10–25 МБ — стоит проверить на медленной сети;
- больше 25 МБ — высокий риск долгого первого запуска.

## Ограничение MVP

Сетевой объём не равен размеру распакованного архива: часть ресурсов может загружаться позже, а HTTP-сжатие уменьшает передачу. Точный лимит 100 МБ следует отдельно проверять по ZIP/папке билда.

Пока события SDK перехватываются через обёртку `YaGames.init()`. Если конкретный движок использует собственный нативный плагин или нестандартную загрузку SDK, понадобится отдельный адаптер.
